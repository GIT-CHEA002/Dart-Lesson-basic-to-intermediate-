# Understanding Dart Project Folder Structure

A typical Dart project has the following folder and file structure:

```text
my_project/
├── .dart_tool/              # Generated by Dart tooling
├── .git/                    # Git version-control files
├── bin/                     # Executable entry points
│   └── my_project.dart
├── lib/                     # Main reusable source code
│   ├── src/                 # Private implementation details
│   │   └── some_class.dart
│   └── my_project.dart      # Public API
├── test/                    # Unit and widget tests
│   └── my_project_test.dart
├── example/                 # Example usage of the package
├── analysis_options.yaml    # Dart analyzer and linter rules
├── pubspec.yaml             # Project metadata and dependencies
├── pubspec.lock             # Locked dependency versions
├── CHANGELOG.md             # Project change history
├── README.md                # Project documentation
└── LICENSE                  # Project license
```

## Folder and File Explanation

### `.dart_tool/`

Contains files generated automatically by Dart tooling.

* Used for build and package-management information.
* Usually should **not** be edited manually.
* Typically excluded from Git.

### `.git/`

Contains Git's internal files for version control.

It is created when you run:

```bash
git init
```

### `bin/`

Contains executable entry points for a Dart application.

Example:

```text
bin/
└── my_project.dart
```

You can run the application with:

```bash
dart run
```

### `lib/`

Contains the main reusable Dart source code.

This is the most important directory for Dart packages and libraries.

```text
lib/
├── src/
│   └── some_class.dart
└── my_project.dart
```

### `lib/src/`

Usually contains **private implementation code**.

Code inside `src/` is generally intended to be used internally by the package rather than directly by package users.

### `lib/my_project.dart`

This is commonly the **public API** of the package.

It can export classes and functions from `src/`:

```dart
export 'src/some_class.dart';
```

Then users can import the public API:

```dart
import 'package:my_project/my_project.dart';
```

### `test/`

Contains automated tests for your project.

Example:

```text
test/
└── my_project_test.dart
```

Tests can be run with:

```bash
dart test
```

### `example/`

Contains example applications showing how to use the package.

This is especially useful when creating reusable Dart packages.

### `pubspec.yaml`

The main configuration file of a Dart project.

It contains information such as:

* Project name
* Version
* Description
* Dependencies
* Development dependencies
* SDK constraints

Example:

```yaml
name: my_project
description: A sample Dart project

environment:
  sdk: ^3.0.0

dependencies:
  http: ^1.0.0
```

### `pubspec.lock`

Stores the exact versions of dependencies resolved for the project.

For example, if your project depends on `http`, the lock file records the specific version that was resolved.

### `analysis_options.yaml`

Contains Dart analyzer and linter configuration.

It controls rules such as:

* Code style
* Warnings
* Errors
* Lint rules

### `README.md`

Contains documentation about the project.

Usually includes:

* What the project does
* Installation instructions
* Usage examples
* API information

### `CHANGELOG.md`

Keeps a history of changes made to the project.

Example:

```md
## 1.1.0

- Added user authentication.
- Fixed login validation.

## 1.0.0

- Initial release.
```

### `LICENSE`

Specifies how other people are allowed to use, modify, and distribute your project.

---

## Adding a New Package

To add a dependency to your Dart project, use:

```bash
dart pub add package_name
```

For example:

```bash
dart pub add http
```

This updates your `pubspec.yaml` and resolves the package dependency.
